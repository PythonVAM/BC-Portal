Roles in this option

As the proposed workflow, the roles are rigid and pervasive. The only addition is an optional FBP approval the SET BC Lead can invoke before Group. The SET BC Lead is always an FP&A person — in every option.

SET BC Lead  +  BC Lead → FP&AThe SET BC Lead and BC Lead are treated as one combined role, fulfilled by the same FP&A person who orchestrates the BC.
BC Contributor → FBP  or  GFS Analyst
FBP Approver → FBPOptional approval gate. If the SET BC Lead chooses, the balanced BC is routed to an FBP for approval before it goes to Group — replacing today's offline sign-off.

About this option

⚙Constraints
  • Roles are rigid and pervasive. Exactly as the proposed workflow — a SET BC Lead is only ever a Lead, a Contributor only ever a Contributor.
  • Contributors are Finance roles. A Contributor is assumed to be either an FBP or a GFS Analyst.
  • FBP approval is optional. The SET BC Lead may route the balanced BC to an FBP for approval before submitting to Group, or submit straight to Group.
✓Advantages
  • Removes the offline approval. The FBP approval SET BC Leads do offline today becomes an optional, in-system step — captured and auditable.
  • Minimal deviation and re-work. The workflow stays very close to what's been built so far, so it needs little change from the proposed design.
  • Full SET Area visibility for the Lead. Every BC is still orchestrated by the SET BC Lead, who reliably sees all BCs in their SET Area.
⚠Trade-offs
  • Roles stay rigid and pervasive. This option doesn't address the inflexibility of fixed roles — an FBP who would normally contribute still can't, and the same change-impact considerations as the proposed workflow apply.

Best-practice assessment

This isn't a SOX-controlled process, so controls should be proportionate to risk. Against common governance principles — segregation of duties, four-eyes, auditability and RACI — this option rates:
